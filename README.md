# SAP codelab

Create a memo, pick a place on the map, and get a notification (title + first 140 characters)
when you come within **200 m** of it, even if the app is in the background or not running.

## Setup

1. Open in Android Studio (Gradle 9.8, AGP 9.4, JDK 17+).
2. Run `app`. A Maps key restricted to this app is included (`maps.properties`), and debug builds are
   signed with the shared `keystore/debug.keystore` it is restricted to. To use your own key, set
   `MAPS_API_KEY=...` in `local.properties`.
3. In the app, grant location, notifications, then **"Allow all the time"** from the banner on the home screen.

## Architecture

Single module with package layers: `ui` → `domain` → `data` (+ `core`, `background`).
Compose + MVI (`BaseViewModel` with a `@Composable uiState()`), Navigation 3, Hilt, Room 3.
Play services and Google Maps are wrapped (`data/location`, `ui/components/map`), so another provider can replace them.

## How location tracking works

The app cannot keep a GPS stream open (battery), so it combines two mechanisms that back each other up.

### 1. Geofences (primary)

- Every open memo gets a **200 m circular geofence** registered with Play services (`data/location/source/GeofenceDataSourceImpl`). The geofence id is the memo id.
- Play services does the watching with the OS low-power location stack, outside the app process. On *enter* it fires a `PendingIntent` to `GeofenceBroadcastReceiver`, which wakes the app even when it is closed.
- The receiver notifies through `GeofenceTriggerHandler` (implemented in `background/`), marks the memo as reminded, and removes that memo's geofence. **Each memo reminds once.**
- `INITIAL_TRIGGER_ENTER` reminds right away when the device is already inside the circle at registration.
- The `PendingIntent` uses a fixed request code. Play services ties registered geofences to the intent, so the code must not change between runs.
- Android allows **100 geofences per app**. With more open memos, the 100 nearest to the current location are watched (the periodic check re-syncs as the user moves). Without a location fix, the newest 100 are used.
- Registration is **replace-all** (`replaceGeofences`): the set of watched memos changes with every create, done and reminder, so one "make Play services match the database" call is simpler than tracking individual registrations, and it also repairs a lost registration.

### 2. Periodic check (safety net)

`ProximityCheckWorker` is a WorkManager periodic job (**every 15 min**, the platform minimum). Each run:

1. `NotifyNearbyMemosUseCase`: with no open memos it stops (no location request); otherwise it gets the current location and reminds of every memo within 200 m.
2. `SyncGeofencesUseCase`: re-registers the geofences.

This catches geofence events that were delayed or missed, and restores registrations that Play services dropped.

### Background entry points

| Trigger | What runs |
|---|---|
| App process starts (`App`) | Schedules the periodic worker, requests a one-time geofence sync (`GeofenceSyncWorker`) |
| Memo saved | `SaveMemoUseCase` syncs the geofences |
| Location permission gained (home screen) | Geofence sync |
| Device enters a geofence | `GeofenceBroadcastReceiver` → reminder |
| Every 15 min | `ProximityCheckWorker` |
| Reboot or app update (`RestartReceiver`) | Re-schedules the worker and re-registers the geofences, because geofences do not survive either |

### Permissions

`ACCESS_FINE_LOCATION` (needed for geofences), `ACCESS_COARSE_LOCATION`, `ACCESS_BACKGROUND_LOCATION` (to trigger while the app is away, "Allow all the time"), `POST_NOTIFICATIONS` and `RECEIVE_BOOT_COMPLETED`. The home screen shows a banner for whatever is missing. Location and geofence calls are skipped (not failed) when the permission is not granted.

### Nearby queries

Distances are computed in the data layer (`LocationTrackingRepository.distanceMeters`, backed by `Location.distanceBetween`). To avoid loading every memo, the database narrows the candidates first: a latitude/longitude bounding box around the user for the 200 m check, and an ordered `LIMIT` query for the nearest 100. The exact distance is then checked on the few rows returned.

## Database

Room 3 with the bundled SQLite driver, one database (`memos.db`), one table. Schemas are exported to `app/schemas/` and committed with every change.

**Table `memos`** (`MemoEntity`)

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER, primary key, autogenerated | also the geofence id and notification id |
| `title` | TEXT | |
| `description` | TEXT | the notification shows its first 140 characters |
| `latitude` | REAL | WGS84 degrees |
| `longitude` | REAL | WGS84 degrees |
| `isDone` | INTEGER (boolean) | the user marked the memo as done |
| `isReminded` | INTEGER (boolean) | the reminder was shown; a memo reminds only once |

An *active* memo is `isDone = 0 AND isReminded = 0`; only active memos are watched.

**Index:** `(isDone, isReminded, latitude)` serves the location queries: filter on the two flags, then range-scan on latitude.

Bump the version with every schema change and prefer `AutoMigration`. Never use destructive migration in release builds.

## Google Maps API key

The map picker and the preview need a Maps SDK key. It is resolved at build time in `app/build.gradle.kts`, in this order:

1. `MAPS_API_KEY` in **`local.properties`** (git-ignored): use this for your own key.
2. `MAPS_API_KEY` in the committed **`maps.properties`** (project root): a key restricted in Google Cloud to the package `com.sap.codelab` and the SHA-1 of the committed `keystore/debug.keystore`, so the project runs right after cloning. It is the only key allowed in the repository.
3. Empty: the map shows blank tiles.

The value is injected into the manifest as the placeholder `${mapsApiKey}` (the `com.google.android.geo.API_KEY` meta-data). Debug builds are signed with the shared `keystore/debug.keystore` so the restriction matches on every machine. Release builds must use your own key, restricted to your own release signing certificate.

To use your own key, add to `local.properties`:
```
MAPS_API_KEY=your-key
```

## Try it on an emulator

Create a memo, put the app in the background, then move the device onto the point:
```
adb emu geo fix <longitude> <latitude>
```
